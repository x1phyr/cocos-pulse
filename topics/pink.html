PinK & Agent

聚合（截至 2026-09-10）。条目来自日刊 09-08 / 09-09，并回填论坛 /latest 新鲜信号；论坛仅摘要级，不转全文。

DEEP // PinK Alpha

楼主 + 官方口径
楼主核心观点 · @weibo（官方）

「这是一个 Alpha 版……请勿用于生产环境（或请做好数据备份）。」开放 HarmonyOS 原生构建、Spine/资源预览、场景参考图 + Chat/MCP 截图；管理员从回帖选人发激活码；「Beta 版发布时间还需要延后」。

来源 forum #177288 · 下载 pink.sud.tech

楼下主旋律 · 社区氛围

回复 25+，几乎全是「求激活码 / 蹲码」；有人问 CLI 与 PinK 是否同步发版。当氛围条读，不当技术结论。

DEEP // UI 还用手搭吗？

楼主 + 高赞一句
楼主核心 · @GlobalThis

「大佬们现在 ui 界面还用手搭吗，还是直接用 ai 全自动了，求分享。」——和 PinK / peanut-pod / Game Agent 撞在同一条时间线上。

来源 forum #177299

高赞 / 代表性回帖

@chenyu0532：「用了几次蓝湖+unity-mcp+codeX……慢，还不一定准，有这时间我自己就搭完了。」楼主回：「看到大家都还是手搭我就放心了。」另有声音认为 MCP / 规则化生成会很快普及——先搞好 MCP。

DEEP // peanut-pod

可验收编辑通道
楼主核心 · @catfish

痛点：AI 改得了脚本、碰不动 Prefab/Scene；不敢把工程交给「随便改盘」的 Agent；换 IDE 成本高；改完无法验收。peanut-pod：不换 Creator，装成宿主扩展，用 MCP 受控查资产 / 改 Prefab·Scene / 刷新预览并读错误——写源文件与 .meta，不写 library/。

来源 forum #177235

楼主补充 · 业务插件 / 验收闭环

业务插件是装进 Creator 的平台插件（非 Agent 里的 Tool）；验收闭环强调预览刷新 + 控制台错误回读。楼下追问「操作场景的 MCP 已经有不少，业务插件和验收闭环能细说吗」——赛道已从「能改」进到「能验收」。
