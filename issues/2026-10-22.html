01 / HEADLINE

beta 分支再收一修：#1003 修多选删同名节点后 undo 漏恢复，#1005 补脚本热重载 import map

cli 的 Beta 前修补继续直接往 v0.2.0-beta.0 分支上打，这一天又收一条、再挂一条，分支领先 main 增至 4 条。#1003（YuchenWell，+163 / −5，wuzhiming 于 10-21 19:21 CST 合入）修的是多选删除同名节点后 undo 可能漏恢复：旧逻辑按快照路径（如 /Cube）找到的却是另一个同名节点 A，上层误以为 B 已存在而跳过恢复；现在路径查询结果必须与快照 UUID 一致，也顺带避免删除时误删 A。DecviL 18:13 CST 开的 #1004 7 分钟后关闭，18:24 CST 以同内容重开为 #1005（+200 / −17，OPEN）：场景开着时新建脚本，浏览器场景包里的 Node 兼容 shim 让环境判断误以为在 Node 下、跳过 import map 刷新，于是新编译的 __unresolved_* 依赖解析不了、组件加载失败；修复后以 no-store 拉最新 import map 再重载，PR 说明需与 PinK 侧等待 preview 编译目标完成的修复配套。

02 / SIGNAL

cocos4 #371：Graphics 每个子模型固定吃约 2.25 MiB GPU 缓冲，提议按需分配

四仓里 cocos4 唯一的新动静是一条写得很扎实的需求 issue，做 UI 遮罩多的项目值得关注。#371（llsansun，10-21 16:47 CST）指出 Cocos Creator 3.8.8 中 Graphics.activeSubModel() 为每个子模型固定申请 65535 × vertexStride 的顶点缓冲与 131070 × 2 字节的索引缓冲，按当前 32 字节 stride 算约 2.25 MiB；矩形、椭圆 Mask 只需几个顶点，多个小遮罩同时存在时冗余累加。建议按实际顶点 / 索引数初始化、不足时翻倍扩容、clear() 保留容量复用，并保留分块策略与 16 位索引限制、分别验证 Web 与原生。暂无官方回复。同一窗口 cocos-engine 零提交零新 PR，只有 #19250（asset-db 启动竞态）下多了一句网友在试 workaround；cocos-docs 完全静音。
