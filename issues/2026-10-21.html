01 / HEADLINE

cli 修本地服务跨域口子：拒绝跨站与 DNS rebinding 请求，默认只绑 127.0.0.1（#1002）

这条值得每个开着 PinK / cocos-cli 又顺手逛网页的人看一眼，因为修的是本机服务谁都能调的问题。周二 20:06 CST main 上出现一条「Merge commit from fork」（e683ccc），20:55 CST 同样内容以 #1002（star-e，+351 / −23）合进 v0.2.0-beta.0 分支，这种 fork 合并形式通常对应私下处理的安全修复。说明写得很直白：HTTP 服务（MCP 端点、项目 API、socket.io）没有鉴权，却返回 Access-Control-Allow-Origin: * 且接受任意 Host 头，用户访问的任何网页都可能直接或经 DNS rebinding 调用 localhost 上的全部 MCP 工具并读到结果。修复后校验 Host（回环、配置的 host、本机网卡 IP）与 Origin（回环、配置 host、vscode-webview: / vscode-file:），回显允许的 Origin 而非 *，未指定 host 时默认绑 127.0.0.1——局域网预览今后要显式配 host；LightFX 烘焙单独起的 Socket.IO 2.x 服务也补了同样的握手校验。不带 Origin 的 MCP 客户端与 CLI 不受影响。

02 / SIGNAL

v0.2.0-beta.0 分支开始收修复：#999 脚本诊断 · #1000 动画图变体保存 · main 新开 #1001

上期 cli 刚拉出 beta 分支，这一天它就领先 main 三条提交，看得出 Beta 前的修补是直接往分支上打。#999（bofeng-song，14:16 CST 合入）让脚本模块解析失败时报出源文件、import 说明符与编译目标，不再只看到哈希 chunk 和 __unresolved_6 占位符，还加了 no-store 的诊断端点反查原始 import。#1000（looopmax，20:02 CST）修动画图变体用模型内 AnimationClip 做覆盖时报「Expected cc.AnimationClip」存不了的问题。main 上新开 #1001（doommm，[break]，+2129）：资源移动遇重名不再强制自动改名，新增 preflightMoveAsset 预检与一次性 token，让宿主让用户选覆盖 / 改名 / 取消；七月的老 PR #745 场景服务 lib 接口重构未合即关。
